# タスクの扱い方

タスクは `sb task` だけで扱う（コマンドは sb の README の task の節）。タスクのファイルを直接書かない。

## 1. タスクと予定

- 区分は2つ。「タスク」はやること（期限を持つ）。「予定」は決まった時刻にあること（開始と終了を持つ）。
- 時刻に意味がある物（外出・面談・配送・公開・日課）は予定にする。1つの予定は1つの時間帯だけ。時刻が違えば別の予定にする。終了の時刻が分からなければ空にする。
- 件名は、誰が何をするかが分かる形にする（「実行」「確認」だけにしない）。
- 繰り返す物は `--repeat` で持つ。終えるか取り消すと、次の回が作られる。

## 2. 期限

- 期限は日付だけで渡す（`--due YYYY-MM-DD`）。時刻は付けない。その日の論理日が終わったとき（翌日の 05:00）に期限切れになる。
- 提出日・公開日のような正式な期限は、最後の境目。準備・作成・確認は別のタスクにして、その前に置く。
- 本人が日付を言わない本人のタスクは、見積を付け、今の予定と負荷から当日か翌日の期限を決めて、作ったときの返事で本人に伝える（返事の場が無い定時処理は、本文に「期限はAIの仮置き」と書く）。本人が「もう寝る」「今日は終わり」と言った後に足す物は、翌日にする。
- 期限を後ろへ動かすのは、本人がそのタスクの延期を言ったときだけ。期限切れを消すためだけに動かさない。

## 3. 担当と状態

- 担当は「本人」「エージェント」「本人+エージェント」。
- 状態は次の6つ。
  - `open`: まだ始めていない。
  - `in_progress`: 作業中。
  - `waiting`: 外の何かを待っている。待つ物（何を・誰を）と次に確かめる日を必ず入れ、期限は空にする。次に確かめる日が来ると NOW の「待ち」に出るので、届いていれば `open` に戻して期限を付けるか閉じ、まだなら次に確かめる日を先へ延ばす。待ちを見直すためのタスクを別に作らない。
  - `needs_review`: 本人の確認を待っている。`work/` の作業なら、直して試験が通り、本番へ入れる前。期限は未来に置かない。
  - `done`: 本人が認めた。`work/` の作業なら、本人の承認を受けて本番へ入れ、確かめた後。**本人の承認の言葉を受ける前に done にしない。** ただし taskizer と案件蒸留（distill/projects）は、本人が決めたそれぞれの本文の範囲で、根拠を経緯に残して閉じてよい。
  - `cancelled`: やめた。
- 本人の判断が要る物は、`open` のまま担当を本人にし、本文に決める論点・案・推奨を書く。

## 4. 作る

- 本人がはっきり決めたことだけをタスクにする。推測・仮定・選ばれなかった案はタスクにしない。
- 永続する物を変える実作業は、最初の変更の前にタスクを作り、`in_progress` にする。
- 同じ物が2つあれば1つにまとめ、もう一方は理由「重複」で取り消す。
- 作るときは、件名の中身が分かる ID を付ける（形は sb の README の task の節。付けないと、日本語の件名からは意味の無い ID ができる）。
- 件名・本文に書かない物: 商品名・URL・住所・電話番号・一回きりのコード・連絡の本文・秘密の値。具体的な物は元の記録に残し、タスクからは指すだけにする。

## 5. 進める・閉じる

- 返事の前に `sb task show` で今の状態を読み直す。
- 途中で止めるときは、終わった範囲・変えたファイル・次の一手を `sb task note` に書く。
- 技術的に終わったら `needs_review` にし、成果物・確かめたこと・残るリスクを書く。作業の場所は絶対パスで、repo の作業なら commit も書く。`work/` の作業は本番へ入れずに止め、変えた物（差分・変えた文書の全文）と本番で変わること（取り込み・定時処理・配置・data の移動）も書く。
- 本人が承認したら本番へ入れて確かめ、`done` にする。
- done の後に別の変更をするときは、新しいタスクを作る。
- 同じやり方を繰り返さない。2回目は別のやり方、3回目は止めて `waiting` にする。本人の操作が要るなら、その操作の本人タスクを別に作る。
- 案件全体の完了を言われたら、その案件の active のタスクを全部挙げて閉じる。ほかの案件には触らない。

## 6. 見せる

- 「今日やること」を聞かれたら、NOW の節（今日の予定・期限切れ・今日まで・明日まで・本人の確認待ち・待ち・作業中）を全部出す。まとめて隠さない。
- 「進んだか」「返事が来たか」は、タスクの有無だけで決めない。その日の連絡・会話の蒸留と案件メモも見る。見つからないことを「進んでいない」の根拠にしない。
